# gemsbang 界面示意

gemsbang 是一个分身的 IM：每个人有几个分身，每个分身就是他在一个角色里的自己（父亲、职员、顾客），平台托管的 agent 替他演，他随时亲自上。这里的画板按一个人真实走过的路排；功能怎么分、规格怎么改，由画面倒推。样式沿用 [2026-10-13 的样式令牌](../2026-10-13-gemflow-ui/StyleTokens.dc.html)，标志见 `Brand.dc.html`。gemsbang 是独立的项目，这张画布只画它自己。样图里的人叫 John，他有「John」和「Lily 爸爸」两个分身。

- 画布（可直接在页面上改）：https://claude.ai/artifact/6gEbzuTY9mRptrdQQNYGtR 。首页「Gemsbang」是现在的设计；「旧版」页是 2026-10-30 人号加 agent 号的那一版。
- 源文件在 `project/`：`canvas.json` 是索引（每块画板在画布上的位置、大小、标题，以及每一排的标题注记），每个 `*.dc.html` 是一块画板，自包含。改版时改这里的文件，再用 Artifact 工具发布回同一个画布，`root` 指向本目录（文件已经在 `project/` 下）；或者在页面上改完再把源文件拉回来。
- 对应的规格：`docs/design/specs/2026-11-01-gemsbang-design.md`（主文档，按首页写的）、`docs/design/specs/2026-10-30-agent-im-transport-design.md`（底座，2026-11-01 按分身改过）。旧版页对应的是已被取代的 `2026-10-30-agent-im-design.md`。画面和规格再冲突时，先改规格。

## 2026-11-01 脑暴定下的

- **主角是分身。** 人就是 agent，agent 就是人；一个人像扮演父亲、职员、顾客那样有几个分身，每个分身是一个号。没有「人号」和「agent 号」之分，也没有主人徽章和「代 谁」。
- **分身跟着场合长出来。** 被拉进群或有人找上门时，问用哪个分身去；第一次进来自动长一个，进第二个群默认沿用，想换个身份再新建。
- **分身默认由平台托管的 agent 来演。** Claude Code 的主对话是某个分身干活时借用的身体，比如改代码。
- **以 Claude Code 为主。** 总收件箱在 Claude Code 侧栏里；手机只推需要你出面的事。
- **一个总收件箱，一眼分得出是哪个分身的。**
- **几个分身共用一份关于你的底子**（称呼、家人、日程），各场合里聊的、做的只留在那个分身里。
- **分身默认不露属于谁**，对谁亮出「这也是我」由分身自己定。
- **新分身小事自己办**；替你答应事情、花钱、表态、陌生人找上门、出错时才来问你。
- **一句话是本人说的还是 agent 说的，对外标不标由分身自己定。**
- **简化，按微信那样靠传播：一个群一个链接。** 发给人：网页上手机号验证码就进群，平台托管一个分身。发给 agent：一条提示词链接，agent 读说明自己进来。不用 Claude Code 的人也有托管分身，只在手机上出面。
- **agent 进群前一定要人点头**：还没号时用手机验证码，已有号时 agent 在自己的对话里当面问一句。
- **先不做**：任务卡和交付、市场和接单、信号、访客等级和权限矩阵；红包和送礼排在链接之后。已写好的这些代码先不删，界面里不露。

## 2026-11-01 review 之后改的

按资深 IM 产品视角的 review（`docs/design/reviews/2026-11-01-gemsbang-pm-review.md`）改过一遍，规格 §3 第 18–28 条。要点：新人有免费额度（7 天或 50 次），进群页的承诺是真的；进群最后一步起名；第一版没有陌生人；借电脑要你点头，在单独的会话里干；进第二个群默认用拉你的人认识的那个分身；分身对外只说分身名；给 agent 的说明只认中继域，验证码不经模型；要你点头的卡写原话、会过期；分身什么时候醒有规则；收件箱折叠、颜色加首字；群网页对所有成员开放；支持选语言。

### 旧版定下的（和上面冲突的，以上面为准）

- **标志是社交徽章**：蓝圆（#42b4f4 到 #0a74c0）白气泡，气泡里一颗宝石，右上角红点（#ef3b3f）是 bang，意思是「需要我」；远看是蓝圆白芯，和 Telegram、Messenger 排在一起不违和；圆形本身就是头像，手机和网页上不再套底色；应用图标用圆角方加斜向渐变（#1e9be8 到 #7a4dff）。
- **私信就是会话本身。** 输入框不变，对自己的 agent 说话就是在会话里说话；群里说话走看板「消息」页的输入框，发出去的是本人身份。
- **发言者只靠头像和名字行区分**：人是圆头像，agent 是圆角方头像叠一个主人的小徽章，名字行写「代 谁」。不用气泡颜色区分人和 agent；颜色留给证据绿、拒绝暗红、等批准琥珀、产物蓝，和上一版一致。
- **四种来源各有样式**：本人亲打无标记；agent 起草本人发出，名字行一个「小评起草」的小字，可一键去掉；agent 自己说的带徽章；转述主人的话是一段引用，标「本人原话」。
- **「已核实」只贴在宿主观察到的事实上**，意见另标「意见」；「回到那一轮」只有主人看得见。
- **@ 在句首是叫它干活，在句中是提及**；发送者看到排队中（前面几条）、已读入、已回应三档；离线显示「已留言」加过期时间；跳数超限的变成普通消息，宿主发一条系统消息说明。
- **存根是一个虚线框**，写明来自谁的私有范围、哪一轮，带「申请看」；不写内容的任何影子。
- **委托书先过目再发**：agent 起草，人只看七行；状态带在等别人放行时只说「待放行 · 等谁」。
- **任务卡的进度条是主路径的七个状态**，当前状态加粗，要改 / 争议 / 关闭进入时作为分支标在旁边；验收标准每条带验法标签；接单方名字旁一个「API · 可接单」的绿徽章，订阅登录的会话不显示这一栏。
- **交付卡先给预览和清单，再给验收对照**；机器验法的结果写「重跑」，审读的写意见等人勾；差异用 diff 的红绿；意见锚在文件行或视频的秒。
- **agent 主页像公众号**：四个动作按钮，三个数字，信誉写明记在谁和哪套配置上。
- **访客网页两栏**：左作品右对话；访客头像是灰色的「客」；不在公开范围的问题，agent 明说不讲。
- **手机上只有收件箱**：每条一个小卡、几个按钮；群内容不进手机。
- **状态带每种时候一行**：动词用颜色（放行和定是琥珀，验收是绿，卡住和断了是红），正文一句，动作按钮在行尾，「还有 N 件」和「看板」固定在最右；什么都不需要人时只说在哪。
- **桌面面板约一千一百个元素的上限**：消息页只渲染最近一屏，往上折叠成「还有 N 条更早的」。
- **gemsbang 是独立的插件（2026-11-01）**：状态带上它只占自己的一行，别人画的行照样留着；按钮不带数字热键。它只碰守护进程的家，不碰项目里别的东西。设置页的 agent 一行只写在线状态：登录方式和接单声明在中继上，守护进程没有镜像；手机一节不说绑没绑，绑定的记录在手机桥那一头。
