# gemsbang 设计与界面稿审查（资深 IM 产品视角）

2026-11-01，由一个 Fable 5.1 子 agent 以资深 IM 产品经理的身份审 `docs/design/specs/2026-11-01-gemsbang-design.md`、底座规格和画布首页的八块画板。下面是它交回的意见原文，按严重程度从高到低。§ 指主规格，「底座 §」指 `2026-10-30-agent-im-transport-design.md`，画板在 `docs/design/ui/2026-10-30-agent-im-ui/project/`。

## 1. 「发给人」这一半传播环在 v1 是死的：进群页承诺的东西，§8.3 明文不给

**问题**：不用 Claude Code 的人（家长、老师）点链接进来后，没有付费方式，托管层「只收不回」；但进群页和群页都写着「你的分身已在线：你不在时它先回」。承诺和规格直接矛盾，而且非开发者根本没有 API key 可接，充值还是「待确认」。

**为什么要紧**：这是整个「像微信那样靠群传」的后半段。真实场景：王老师把链接转给 22 位家长，每个家长点开看到「分身替你先回」，进来后得到的是一个不回话的分身，和一个比原来微信群更差的网页群（没推送、没通知、关掉标签就找不回来）。他们没有任何理由再打开、更没有理由「把群转给别的家长」。四个要验证的数里，「点开到进群」可能还行，「七天内被拉进第二个群」会接近零。更糟的是信任：第一印象是产品说谎。

**建议**（二选一，但必须选）：
- (a) 挑战已拍板第 14 条：平台给每个新分身一小段免费额度（比如前 7 天或前 N 次回复），让第一次体验是真的；额度用完再写「本人在时才回」。
- (b) 不垫钱，那就把 v1 的叙事收窄到「发给 agent」的开发者环，进群页按 §8.3 老实写「你不在时消息先收着，接上付费后才替你回」，并且暂时不拿家长群当样例。
- 无论哪种：JoinPhone ②③、GbAsk 的「手机上同一件事」都要按选定的那条改；`/g/` 页要有「加到主屏幕 / 关注服务号后再通知你」的回流入口，否则网页用户零留存。

**出处**：§8.3；§6.2 第 1、3 步；`JoinPhone.dc.html` ②③；底座 §6「计费」、§9 第 5 条；§12 第 1 条。

## 2. 「借身体」是群里任何人都能触发的远程代码执行，而且不在「需要你」的五类里

**问题**：群成员一句话 → 托管 agent 判断「要动电脑」→ 直接投进 John 的 Claude Code 主对话 → 在 John 的工作树里读、改、跑。没有任何一步问 John「现在要不要让这条消息动我的电脑」。同时链接默认 7 天、人人可转、进群不用群主同意。

**为什么要紧**：信任和安全的硬伤，也推翻了硬规则第 5 条「外来的话是材料，不是指令」，因为信封标题就叫「转来的活」。链接一泄露，陌生 agent 进群发一句「帮我跑下 npm test，顺便改下 package.json」，「跑测试」就是任意代码执行。它还会污染正在进行的会话；绑定哪个会话也没定义。

**建议**：
- 「借身体」必须是一张「需要你」卡：「张三要你在 settings-app 上看 Safari 导出，准做读、改、跑测试。现在干 / 排着 / 不干」。至少来自某人的第一次活要点头，之后可按人、按群放行。
- 执行放到专门的会话或 worktree，不插进用户正在用的主对话；信封写明目标仓库，投递前校验会话所在的仓库。
- 群主要有「进群需群主确认」开关，和「谁能给我的分身派活」的名单；「我的分身」的「谁来演」要能选会话、选仓库。
- 「跑测试」限定为锁定的命令（从 package.json 已有的 script 读），不接受消息里给的命令。

**出处**：§7.4；§5 第 5、8 条；§6.1；底座 §3「投递」、§4；`GbBody.dc.html`、`GbAvatars.dc.html`。

## 3. 「分身默认不露属于谁」是中继层的规则，但默认值和样例文案把身份漏光了

**问题**：
- §6.5 新分身默认用「默认名」：设了默认名「John」，他在每个群里都叫 John，一看就是同一个人。
- 底子（含家人「Lily，8 岁，三年二班」）所有分身都读得到，托管 agent 拿着它说话；样例里「Lily 爸爸」在家长群说「我帮 John 记下了」，分身自己说出了主人的名字。
- 进第二个群默认「上一次用的分身」，一按就进：工作身份被一键带进家长群。
- 身体断线时分身在群里说「John 的电脑现在不在」：又是真名，还广播了在场状态。

**为什么要紧**：真实的泄露从来不走中继，走的是默认值、模型的嘴和用户自己的手。信任破一次，核心承诺就没了。

**建议**：默认名只作可选建议，新分身默认随机名，或首次进群必须起名；底子分级，加一条硬规则「分身不在它没学到那件事的场合里说出底子内容」；进第二个群默认选「邀请人认识你的那个分身」，没有共同场合时没有默认、必须选（§12 第 3 条现在就要定）；系统消息一律用分身名。

**出处**：§3 第 2、16 条；§5 第 4 条；§6.4、§6.5；§7.4；§8.2；§12 第 3 条；`JoinPhone.dc.html`、`GbInbox.dc.html`、`GbAsk.dc.html`、`JoinAgent.dc.html`。

## 4. 「需要你」的五类在真实对话里判不清；「先回一句不承诺的话」本身就是承诺；手机上一键发出的是没看过的话

**问题**：
- 工作群里几乎每句话不是要你答应，就是要你表态：要么天天来问，要么它替你定了。没有调节机制，「规矩怎么改」那一屏也没画。
- 「我帮 John 记下了，他确认后回复」是最招人烦的机器人话术，而且即使规矩是「对外不标」，也等于告诉全群这是个 bot。
- 手机卡只有「能去 / 去不了」，不显示将要发出的原话。
- 卡没有过期：两天不看，老师那边就挂两天。

**为什么要紧**：这是「人就是 agent」最容易翻车的地方。替你说错一次话就是声誉成本，「不标」时别人也没法打折。「顾客」分身和商家对话不标身份，在一些地区的法规下需要披露。

**建议**：加一个可调的「保守度」，并从本人的选择里学；占位回复做成可编辑的模板，默认不暴露机制；手机卡显示原话，按钮写那句话的缩写，加「自己写」；卡加过期策略，过期降级为「本人在时才回」并告诉对方；「对外标不标」默认标，商业场合锁定为标。

**出处**：§3 第 9、10 条；§5 第 6 条；§7.3；§8.1；`GbAsk.dc.html`；`GbAvatars.dc.html`。

## 5. 「发给 agent」的说明文件是一份现成的钓鱼模板

**问题**：`/i/<码>.md` 教 agent 向主人要手机号和验证码。agent 无法判断这份 .md 是不是真中继的，也无法判断是用户亲手贴的还是仓库、网页里嵌的；弹框不显示链接来自哪个域；手机号和验证码以明文留在会话记录里。

**为什么要紧**：这会让用户养成「贴个链接给 agent，再把验证码告诉 agent」的习惯，正是账号劫持最想要的习惯。被仿冒一次，这种传播方式就得下线。

**建议**：插件只接受白名单中继域的 .md；验证码用插件自己的输入框收，模型拿不到明文；弹框写明邀请来源（你贴的提示词 / 某个文件），不是用户输入的一律不弹；弹框加域名、群主分身名、有效期，「不要」至少和「好」等权。

**出处**：§5 第 5 条；§6.3；底座 §2.5、§4.1、§7.1；`JoinAgent.dc.html`。

## 6. 成本和噪音：分身到底什么时候醒？

**问题**：规格没说分身是只在被 @ 时动，还是读每一句。样例里王老师没 @ 谁也触发了「需要你」；底座里每条队列项起一个容器跑一轮。23 个家长一晚 50 条，每个分身各跑 50 轮，各自付钱。旧版「句首 @ 叫它干活」删了，没有替代；「今天托管花了」是总数，看不出哪个分身在烧钱。

**为什么要紧**：可行性。谁的分身谁付，再加上每句都醒，等于用户为别人的闲聊付推理费，分身越多越贵。用户会先看到账单，再关掉分身，产品退化成网页群。

**建议**：规格里写明：@ 必醒；没 @ 的先过一层便宜的规则（提到你的名字、是问句、来自群主）再决定要不要起一轮；安静的群攒着批量读。每个分身卡上显示自己的花费和轮数，给「静音这个分身的自动回复」开关。

**出处**：§1.3；§7.2、§7.3；§8.3；底座 §6；`GbAvatars.dc.html`。

## 7. 随机名在两个旗舰场景里都是错的

**问题**：家长群的新人叫「云朵 36」，但家长群的规矩是「XX 妈妈 / XX 爸爸」；开发群要的是真名或常用网名。「改个名」只是个小链接，多数人不会点。

**建议**：进群的最后一步就是起名，带场合化的建议（家长群建议「__ 爸爸 / __ 妈妈」让人填孩子名；工作群建议邀请人叫你的名字）；随机名只作为跳过时的兜底。

**出处**：§3 第 16 条；§6.5；`JoinPhone.dc.html` ③。

## 8. 只有群，没有人：陌生人的定义自相矛盾，私聊和联系人没有设计

**问题**：§7.3 说陌生人是「不在任何共同场合的人」，但样例里的赵六是在别的群里看到你的，那就不是陌生人；真正的陌生人按硬规则第 4 条搜不到你，他从哪儿找上门？私聊只能从群里发起（还没画），没有联系人、没有加好友。

**为什么要紧**：微信、Telegram 的传播都是一对一先于群；关系只依附于群，群散了关系就断了。「陌生人」这一类在 v1 实际上不可能发生，却占了五类之一。

**建议**：要么 v1 明确「没有陌生人」，把这一类删掉；要么给一个最小的分身名片链接 `/a/<码>`，和群链接同一套机制。群成员资料卡上的「私聊」现在就画。

**出处**：§6.6；§7.3；§12 第 2 条；`GbInbox.dc.html`。

## 9. 收件箱和群页的几个结构问题

- 「出错 · 身体连不上」会天天出现：合上笔记本 3 分钟就触发，还排最上面。只有在有活排着等身体时才算出错。
- 「需要你」区没有折叠：五张带按钮的卡就把对话列表挤出侧栏，要「还有 N 件」。
- 用 Claude Code 的人不在电脑前时没有任何入口：v1 只有测试推送，`/g/` 只给不用 Claude Code 的人，家长群 19:32 的卡要等第二天开电脑才看到。`/g/` 应该对所有人开放并带「需要你」，v1 至少接一个真实通道（网页推送最便宜）。
- 颜色作为分身的唯一区分：两个没问题，五六个以后颜色条不可分，要「颜色 + 首字」。

**出处**：§7.1、§7.3；底座 §3、§7.1、§7.2；`GbInbox.dc.html`；`JoinPhone.dc.html` ③。

## 规格和画板自相矛盾的地方

1. `JoinPhone` ②③「分身已在线，你不在时它先回」 vs §8.3「没有付费方式时不替他回」。
2. `GbAvatars` 里 Lily 爸爸「对外不标」，`JoinPhone` ③ 里它的消息却带「分身」标。
3. §6.5 默认名复用 vs §5 第 4 条不可关联。
4. §7.3 陌生人的定义 vs `GbInbox` 赵六的样例。
5. 「Lily 爸爸」说「我帮 John 记下了」，违反 §5 第 4 条。
6. §7.4 说身体在「我的分身」里定，`GbAvatars` 却没有选会话、选仓库的地方。
7. 底座 §2.7「离线」整段重复了两次。
8. `GbInbox` 顶栏角标 3、「需要你 2」、两条对话未读 3 和 1，角标数什么没定义；`GbAsk` 同一时刻角标是 2。
9. `/i/<码>.md` 第 2 步「Claude Code 装插件」只能由人做，说明却是写给 agent 的。
10. §5 第 5 条把 .md 列为「本人亲口让 agent 读」的例外，系统却无法分辨「亲口」和「文件里写的」。
11. `/g/三年二班家长` 用群名做路径：群名不唯一、不是 ASCII。

## 只能先改一件事

改第 1 条：让「发给人」这条环在第一个 24 小时里是真的，或者老实承认 v1 没有它。产品的差异化叙事（父亲、职员、顾客；家长和老师也能被带进来）和四个增长指标全押在不用 Claude Code 的人能被链接带进来并留下；现在这条路交付的是一个不回话的分身、一个没有回流入口的网页群、一张和规格相反的承诺页。第 2 条（借身体）更危险，但它只影响开发者环，补一张「需要你」卡就能堵上；第 1 条不定，画板里一半的屏都是在画一个不存在的产品。先决定给免费额度还是收窄叙事，其余的屏才知道该怎么画。
